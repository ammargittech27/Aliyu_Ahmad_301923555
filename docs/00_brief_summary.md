# Brief CA summary

**Course:** MIT 8103 Advanced Database Systems — First Semester CA, September 2026 cohort
**Total marks:** 40 — Individual practical portfolio, no viva (verification by technical
evidence + progressive GitHub activity).

## What the CA requires

- **Case study.** Each student picks ONE realistic organisation and uses it consistently
  across all five portfolios. State organisation name, business nature, users, major data
  and key operations at the start of the documentation. (This portfolio uses IronCore
  Fitness — see top-level `README.md`.)
- **Five portfolios, plus a final documentation piece.**

| Portfolio | Topic | Marks |
|---|---|---|
| 1 | Database design & modelling | 7 |
| 2 | Query processing & optimisation | 7 |
| 3 | Transactions & concurrency | 7 |
| 4 | NoSQL & advanced data models | 7 |
| 5 | Distributed & cloud database exercise | 6 |
| Final | Documentation & technical reflection | 6 |
| **Total** | | **40** |

- **Deliverables per portfolio.**
  P1: case-study description, ER diagram, relational schema, keys, constraints, normalisation
  explanation. P2: SQL queries, results, execution plans, indexing/optimisation evidence,
  performance analysis. P3: transactions showing commit, rollback, isolation, concurrency
  control, screenshot/output evidence. P4: NoSQL model on the same case, implementation
  evidence, suitability explanation. P5: distributed/cloud discussion or setup —
  replication, sharding, availability, consistency, deployment evidence.
- **GitHub.** Private repo named `advanced-database-portfolio/` with sub-folders
  `portfolio-1-database-design`, `portfolio-2-query-optimisation`,
  `portfolio-3-transactions-concurrency`, `portfolio-4-nosql`,
  `portfolio-5-distributed-cloud`, plus a top-level `README.md`. Commit **progressively** —
  bulk uploads at the deadline reduce marks.
- **LMS submission.** A 2–3 page documentation describing all five activities, naming the
  case study, linking the GitHub repo, attaching screenshots/evidence. (Produced *after*
  the student runs everything — not in this zip.)
- **Marking rubric (40).** Technical correctness 8 · DB design quality 6 · Practical
  implementation 8 · Query & performance analysis 5 · Advanced concepts 5 · Documentation
  & GitHub organisation 5 · Technical reflection 3.
- **Individual work & AI.** Discussion allowed; submitted work must be individual. AI tools
  allowed as learning aids **with a declaration** stating: (i) tool used, (ii) what it was
  used for, (iii) how the output was reviewed/corrected/tested. AI use does **not** remove
  student responsibility for accuracy.
- **Submission checklist (12 items).** Case study stated · all 5 activities done · GitHub
  organised · practical evidence · README explains the work · LMS submission · GitHub link
  works · sources referenced · AI declared · individual technical reflection included.
- **Page limit.** Final documentation is **2–3 pages** only. No other length limits given.
- **Naming.** The 2–3 page documentation will be filed as
  `Bello_Ahmad_2026-A-MIT-0537_Documentation.pdf`.
